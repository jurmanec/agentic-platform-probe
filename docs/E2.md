## Goal

Build a minimal **retrieve → generate** path over a **small fixed corpus** of illustrative marketing-ops docs (rules, FAQs, runbooks). Answers must **cite** source chunks. If nothing relevant is retrieved, **fail closed** — do not invent policy.

This slice answers: *Does grounded retrieval + refusal feel like platform work I want to own?*

Complements E1: tools + deterministic validation vs **corpus as invariant data** + LLM synthesis with citations. See [LLM inference fit](concepts/llm-inference-fit.md).

## Corpus (invariant data)

3–6 short markdown files under `e2/corpus/`, for example:

| Doc | Role |
|-----|------|
| `channel-policy.md` | SMS / email / in-app rules (align with E1 residential stub) |
| `fiber-upgrade-faq.md` | Product FAQ for the fiber upgrade brief |
| `ops-runbook.md` | How ops validates a journey step before activation |

Anonymous, illustrative vocabulary only — no employer or vendor-specific claims.

Corpus is **source of truth**. The model must not invent rules that are not in retrieved chunks.

## Scenarios

### Happy path

**Input:** A question clearly answered in the corpus, e.g.  
*“Is SMS allowed for residential Northeast active segments?”*

**Expected:**

1. Retrieve one or more relevant chunks.
2. Generate a short answer grounded in those chunks.
3. Output structured JSON including:
   - `answer`
   - `citations` (doc id / path + optional excerpt)
   - `status`: `"answered"`

### Fail path (required)

**Input:** A question **outside** the corpus, e.g.  
*“What is the 2099 lunar billboard advertising budget for AcmeCorp?”*

**Expected:**

1. Retrieval returns nothing useful (or scores below a threshold).
2. Model / pipeline **refuses** — no fabricated budget or policy.
3. Output: `status`: `"unknown"` (or `"refused"`), empty or minimal answer, no fake citations.

Run both via CLI fixtures/flags (same spirit as E1 `--path happy|fail`).

---

## Pipeline (conceptual)

```text
query
  → load/chunk corpus markdown
  → lexical retrieve top-k (keyword overlap)
  → if score < threshold → fail closed (`status: unknown`)
  → else LLM answer grounded in chunks + citations
  → structured JSON to stdout
```

Prefer a **simple chain** over a tool-calling agent for E2 (keep the RAG signal clear).

## Done definition

E2 is **frozen** when all of the following are true:

1. **Runnable CLI** loads `XAI_API_KEY` and runs happy path end-to-end.
2. Happy path returns `status: "answered"` with **at least one citation** pointing at a real corpus file.
3. Fail path returns `status: "unknown"` (or `"refused"`) **without** inventing policy/facts.
4. README (or `--help`) documents how to run both paths.
5. No secrets committed; index artifacts gitignored if persisted.
6. [P5_CHARTER.md](../P5_CHARTER.md) status updated; one-paragraph freeze note recorded.
